01

How I approach a build

Connecting app A to app B is the easy part, and it isn't what breaks at 3am. Every build here follows the same three rules — the part that's hard to see in a demo video and is what actually makes an automation trustworthy. The companion projects add a fourth: a claim you cannot check is not evidence.

rule / 01

Exit code 0 proves nothing

Every stage verifies its own output. ffprobe the render against the spec, checksum-read the archive, assert row counts after the load. A job that "succeeded" and produced a 0-byte file is a failure.

rule / 02

Always have a failure path

Uncertain cases route to a human instead of guessing, loops give up loudly instead of hanging forever, and an errorTrigger on every workflow means a break gets paged — not discovered a week later.

rule / 03

Refusing to act is a feature

Two of these deliberately do nothing when the evidence is thin. Automation that acts on noise — scaling budget into a "winner" with 400 impressions — destroys things faster than a human can.

Media & content automation

Media Render Farm (FFmpeg)

04 / media ops

One master video in, every ad format out. Expands a request into a variant matrix (aspect ratio × hook), transcodes serially so the box doesn't thrash, then ffprobes every output — a render that finishes but writes a 0-byte file is treated as a failure, not a success.

Webhook→ Build variant matrix→ FFmpeg (one at a time)→ ffprobe vs spec→ Manifest / reject

Verifies duration, byte size, and actual vs requested dimensions. Renders to .partial then atomically moves — a crash leaves nothing rather than a half-written file that looks finished.

Growth & performance

DCO Engine — creative performance loop

06 / media buying

Joins ad-platform spend to affiliate revenue on sub_id, rolls up per-variant CTR/CVR/CPA/ROAS/EPC, then refuses to decide anything until a variant clears both a volume floor and a significance test. Winners get a capped +20% budget step; losers get paused and automatically queue their own replacement brief.

Every 6h→ Join spend + revenue→ Volume floor→ z-test + Bonferroni→ Scale / pause / hold

Testing six variants at α=0.05 gives a ~26% chance of a false winner. The correction holds that at 5% — so a +40% "lift" at p=0.019 gets held for another cycle rather than scaled. A hard ROAS floor overrides the statistics entirely.

Infrastructure & data

VPS Ops & Nightly Data Pipeline

07 / infra / data

The unglamorous one that keeps everything else alive. SSHes into an Ubuntu VPS, runs a Bash healthcheck that returns JSON, self-heals disk pressure and re-checks that it worked, verifies the backup actually contains bytes, then runs an idempotent Python ETL into Postgres and asserts data quality afterwards.

Nightly 02:00→ Healthcheck → self-heal→ Verify backup→ Python ETL → Postgres→ DQ gate / quarantine

A 60% row-count drop versus the trailing week looks exactly like a quiet day — so it's caught and the load is quarantined. Stale-but-correct dashboards get a question; fresh-but-wrong ones get a decision made on them.
