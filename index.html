01

How I build a workflow

Connecting app A to app B is the easy part, and it isn't what breaks at 3am. These four rules are hard to see in a demo video, and they're what make an automation trustworthy.

rule / 01

Exit code 0 proves nothing

Every stage verifies its own output: ffprobe the render, checksum the backup, assert row counts after the load.

rule / 02

Always have a failure path

Uncertain cases route to a human, loops give up loudly instead of hanging, and an Error Trigger on every workflow means a break gets paged, not discovered next week.

rule / 03

Refusing to act is a feature

When the evidence is thin, the workflow holds. Scaling budget into a "winner" with 400 impressions destroys things faster than a human can.

rule / 04

A claim you can't check isn't evidence

The workflows are tested end to end inside a real n8n, and impact numbers are regenerated from data by a script, tagged as benchmark where they are.

04

How it's tested

"Importable" isn't the same as "works". Every workflow goes through three gates, and each gate has already caught real bugs.

gate / 01 · schema
7 / 7

Checked against n8n's own node schemas

Every node's type, version, parameter names and enum values are validated against the schemas exported from n8n 2.x. It caught nodes whose parameters n8n would have silently ignored.

gate / 02 · lint
0

Data-flow lint findings

A linter for workflow exports flags $json reads after nodes that replace the item, broken $('Node') references and dangling connections.

gate / 03 · e2e
52

End-to-end checks in a real n8n

Each workflow runs its scenarios inside n8n, with every external service mocked and every resolved parameter recorded. It found a dropped item in a batch, a report posting three times, and a hand-off that could never fire.
